4. How the check was set up, and its limitations (full disclosure)
------------------------------------------------------------------
(a) No prebuilt Lean or Mathlib toolchain could be obtained in the
    contributor environment: every Lean distribution host was unreachable
    (elan.lean-lang.org, release-assets.githubusercontent.com,
    objects.githubusercontent.com, leanprover-community.github.io).  The
    compiler and its core-library .olean files therefore had to be built from
    the leanprover/lean4 source tree.

(b) That tree's src/ is one development step ahead of the stage-0 compiler
    used to elaborate it, so four *bootstrap-only* edits to Lean's own
    sources were needed before the core library would elaborate: three
    anonymous instance names were pinned to the names the sources themselves
    reference (Nat.instTrichotomousLt, Nat.instDvd, instIrreflOfAsymm) and
    one `private theorem` was made non-private (List.length_map in
    Init/Omega/IntList.lean) because the older compiler does not implement
    the `import all` visibility form.  None of these edits touches this
    submission, and none of them adds an axiom or alters a proof.

(c) 380 core-library modules were produced.  Six still fail under the older
    compiler (Init.Data.List.Scan.Lemmas, Init.Data.Nat.Power2.Lemmas,
    Init.Data.Nat.Bitwise.Lemmas, Init.Data.Range.Lemmas,
    Init.Data.List.Sort.Lemmas, Init.Data.List.ToArray), so the aggregate
    module Init.olean could not be produced.  A Lean file with no import line
    auto-imports Init, and so cannot be loaded by that bootstrap.  The
    *body* of Proof.lean was therefore checked verbatim under two explicit
    headers instead:

      (i)  minimal — module / prelude / public import of Init.Tactics,
           Init.Omega, Init.RCases, Init.ByCases, Init.Data.Nat.Lemmas;
      (ii) stress  — module / prelude / public import of all 380 built
           modules (including Init.Data.List.Lemmas, Init.Data.Int.*,
           Init.Grind.Tactics and Lean.Data.RBMap).

    Both give 0 errors and identical axiom dependencies.  (ii) shows the
    proof does not depend on the size of the ambient simp or instance set;
    the stress harness was itself validated by confirming that it reports a
    deliberately injected error.  Every module in (i) is a plain Init module
    present in every Lean 4 toolchain and re-exported by Init, so the
    submitted header-less file sees a strict superset of those names.

(d) All simp invocations in the proof are `simp only [...]` with explicit
    lemma lists, so they cannot be affected by the ambient simp set.  The
    only other automation used is omega, decide, rw with explicit rules,
    cases, rcases, obtain, by_cases, subst, all_goals, calc and first.

(e) The bootstrap lived in an ephemeral sandbox and has been torn down, so
    the run above cannot be re-executed from this checkout; the output in
    section 3 is verbatim as recorded.  No GitHub Actions run is attached,
    because the submitting fork has no Actions workflows and no toolchain
    could be fetched there either.  This is disclosed rather than papered
    over: the artefacts in sections 5 and 6 are the reproducible evidence.

(f) Reproduction for any reviewer with normal network access:

        cd submissions/jsp-000243-short-interval-unit-fractions
